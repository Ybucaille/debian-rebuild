Un script détruit un serveur Debian 13, le recrée, le configure, le sécurise et vérifie le tout avec 15 tests. Sans aucune intervention manuelle. Suivez le câble, il fait le même trajet que les paquets.

scripts/rebuild.sh

La matière première

debian-13-genericcloud · sha512 ✓

Tout part de l'image cloud officielle de Debian 13. Avant de s'en servir, le script vérifie sa somme SHA512 contre celle que publie Debian.

Le disque de la VM est adossé à l'image : il n'enregistre que les différences. L'image, elle, n'est jamais modifiée. Détruire la VM ne coûte donc rien.

Assemblée au premier démarrage

cloud-init

Au premier démarrage, cloud-init lit un seul fichier texte et fait tout le reste : le compte d'administration, les mises à jour, les paquets, la configuration. Ce fichier est versionné : deux reconstructions donnent le même serveur.

users:
  - name: admin
    lock_passwd: true      # pas de mot de passe
    ssh_authorized_keys: […]
disable_root: true
ssh_pwauth: false
package_upgrade: true
packages: [nftables, fail2ban,
  unattended-upgrades, nginx]

Tout est fermé, sauf trois portes

nftables · policy drop
22ssh 80http ping 8080

Le pare-feu refuse tout ce qui entre, puis ouvre seulement SSH, HTTP et le ping. SSH n'accepte que les clés : ni root, ni mot de passe. fail2ban bannit une adresse pendant une heure après trois échecs en dix minutes. Les mises à jour de sécurité s'installent seules.

NAT · masquerade

192.168.122.40 → 192.168.0.33 → IP publique de la box

Quand la VM télécharge ses mises à jour, son adresse est réécrite deux fois : par l'hôte, puis par la box. Le serveur de Debian ne voit que l'adresse publique de la box.

Dans l'autre sens, l'hôte ne laisse passer que les réponses aux connexions ouvertes par la VM : c'est le suivi de connexion. Depuis le réseau de la maison, personne ne peut joindre la VM. Seul l'hôte le peut.
